# F02 - Document Recommendation System

## Objective

Implement a document recommendation system that helps
Umbral Web users discover relevant design references,
creative methods, and lessons learned.

Recommendations are generated from selected documents
or the user's search context.

## Recommendation methodology

The recommendation engine reuses the shared retrieval
infrastructure implemented during F01.

The document collection is represented using TF-IDF
vectors with unigrams and bigrams.

English stop words are removed, and cosine similarity
is used to compare document and query vectors.

Cosine similarity is calculated as the dot product
of two vectors divided by the product of their norms.

Documents with positive similarity scores are ranked
from highest to lowest similarity.

The implementation measures lexical similarity through
weighted terms rather than contextual semantic embeddings.

## Recommendation modes

### Document-based recommendations

The user selects an existing document by its identifier.

The recommendation engine compares its vector with
the vectors of the remaining documents.

The selected document is excluded from its own
recommendation results.

Recommendations may belong to different categories.

### Search-context recommendations

The user enters a natural language query.

The query is transformed using the existing TF-IDF
vocabulary and compared with the document collection.

This mode provides recommendations based on the
current search context without storing persistent
user histories.

## Recommendation explanations

Each recommendation contains:

- Document identifier.
- Document title.
- Document category.
- Cosine similarity score.
- Up to five shared relevant terms.
- A textual explanation.

Shared terms are ranked according to the product of
their TF-IDF weights in the compared vectors.

The explanations are derived from actual vector
features rather than generated by a language model.

## Configurable parameters

| Parameter | Default | Purpose |
| --- | --- | --- |
| top_k | 3 | Maximum number of recommendations |
| min_similarity | 0.0 | Minimum accepted similarity |

Documents with zero similarity are always excluded.

The minimum similarity parameter can be adjusted
to filter weak recommendations.

## Running the recommendation system

From the repository root, with the virtual
environment active, run:

```bash
python src/recommendation_cli.py
```

Available options:

1. Recommend by document.
2. Recommend by search query.
3. List available documents.
0. Exit.

## Programmatic usage

```python
from src.recommender import RecommendationEngine

engine = RecommendationEngine()

document_results = engine.recommend_by_document("UW02")

query_results = engine.recommend_by_query(
    "How can we organize a session to generate design ideas?"
)

for result in query_results:
    print(result.document.doc_id)
    print(result.document.title)
    print(result.similarity)
    print(result.explanation)
```

## Limitations

- The collection contains only nine documents.
- Recommendations depend on lexical overlap.
- Synonyms and paraphrases may not be recognized
  when they do not share indexed terms.
- Weak recommendations may appear when documents
  share only general vocabulary.
- No persistent user history is implemented.
- The minimum similarity threshold has not been
  calibrated through a formal relevance evaluation.
- Cosine similarity scores are not confidence
  probabilities or accuracy percentages.
- The current interface is command-line based.

## Potential improvements

1. Evaluate and calibrate the minimum similarity
   threshold using human relevance judgments.

2. Compare TF-IDF retrieval against contextual
   embedding-based representations.

These are proposed improvements and have not been
implemented or formally evaluated during F02.
